# PlayIdle scene-action(scene 播動畫)設計

> 日期:2026-06-06 · 狀態:**設計核准,待寫實作計畫(writing-plans)**
> 動機來源:多重身份系統的聖騎士宣誓演出需要「下跪祈禱」動畫;PlayIdle 本身是 IDEAS §1b 早就想要的通用 scene 能力(不只服務宣誓)。**先獨立一輪**落地,身份系統 round 2 再騎上來。
> 相關:`docs/superpowers/specs/2026-06-06-identity-system-design.md`(下游,封存待此前置)。

## 目標

讓 scene 的某個 phase 能讓指定 actor **播放一段指定 idle 動畫**(下跪、祈禱、手勢…),動畫與 phase 對齊、結束後 actor 自然回到 AI。這是 SCEN 目前缺的第四種 action(現有只有 Dialog / Package / Timer)。

## 背景:為什麼走 scene phase fragment

- `SceneAction.TypeEnum` 只有 Dialog / Package / Timer——**沒有原生「播動畫」action**。
- Skyrim 演出動畫的標準路子:SCEN 掛 `SceneAdapter`,某 phase 的 begin fragment 呼叫 `akActor.PlayIdle(idle)`。
- Mutagen 0.53.1 **已暴露**所需型別:`Scene.VirtualMachineAdapter` = `SceneAdapter`,其 `ScriptFragments`(`SceneScriptFragments`)帶 `PhaseFragments[]`(`ScenePhaseFragment`,per-phase begin/end fragment)。可行性確認。
- 比起 Package action(procedure 式,適合「走過去坐下」這種持續行為,演不出一次性、對齊時點的下跪),phase fragment 最精準、idle event 任意、結束回 AI。

ModForge 已會寫兩種 fragment 家族(`QuestAdapter` 任務階段、TIF 對話 ResultScript);本設計新增**第三種:scene phase fragment**,但產生/掛載手法與前兩者同構。

## Spec 增量(最小)

`SceneActionSpec` 加一個欄位:

```csharp
public string Idle { get; set; } = "";   // ref → 一個 IDLE 記錄;設了 = 此 action 播該 idle(取代 Package/Timer)
```

作者用法(在某 phase 加一個 idle action):

```jsonc
// scene 的某個 phase action:alias 1 在 phase 0 開始時播「下跪祈禱」idle
{ "actor": 1, "startPhase": 0, "idle": "Skyrim.esm:0x0XXXXXX" }
```

- `idle` 是 IDLE 記錄 ref(`<master>:0xID` 或 spec 內 editorId),用 `find` 探得、依 [[vanilla-nif-paths-must-be-verified]] 紀律驗證 FormID。
- 一個 action 的判定優先序:`idle` 非空 → Idle action;否則 `timerSeconds>0` → Timer;否則有 `package` → Package;否則 Dialog(沿用既有邏輯,只在前面加一支 idle 分支)。

## Build 機制

1. 掃描每個 scene 的所有 phase action,收集 idle actions `(sceneEd, actor alias, phaseIndex, idleRef)`。
2. 在該 SCEN 上**併入**(不覆寫)`SceneAdapter`:`ScriptFragments.PhaseFragments` 對每個用到的 phase 加一個 begin fragment,指向 `SF_<sceneEd>` 腳本的 `Fragment_<n>`。沿用 adapter 合併紀律(見 [[sm-quest-journal-progression]]:WireQuestStages **合併**進既有 adapter,勿 `=` 覆寫——SceneAdapter 同理,scene 若已有其他 fragment 不能清掉)。
3. idle ref 在 pass 2 解析成 FormKey(複用 `TryResolveRef`),fragment source 用其 form / editorId 取得 IDLE。

## Fragment 來源產生器(純函式、可測)

新增 `GenerateSceneFragmentSource(SceneSpec)`,鏡像現有 `GenerateQuestFragmentSource`(string in/out、無 Wine/Skyrim.esm 依賴、單元可測):

```papyrus
Scriptname SF_<sceneEd> extends Scene
; AUTO-GENERATED by ModForge — scene phase idle playback.

Function Fragment_<n>()
    ; phase <p>: alias <a> plays idle <idleEd>
    Actor a = (GetOwningQuest() as <questScript>).<aliasProp>.GetActorReference()
    a.PlayIdle(<idleProp>)
EndFunction
```

- 取 actor:scene 的 actor 是 host quest 的 alias;fragment 透過 `GetOwningQuest()` + alias property 取 `ObjectReference`/`Actor`。property 由 `package` 在掛 VMAD 時填(idle 與 alias 各一個 property)。
- `package` 指令:編譯 `SF_<sceneEd>.psc`(複用既有 Papyrus.Compile 管線、embed header 解法),並把 `SceneAdapter` VMAD + properties 掛上 SCEN(鏡像 quest/TIF fragment 的 `package` 掛載步驟)。
- exact 欄位(`ScenePhaseFragment` 的 Stage/ScriptName/FragmentName、fragment 編號慣例)在 plan 階段對 Mutagen API 精修。

## 演出 composition(YAGNI)

MVP **一個 action 一個 idle**;「保持跪姿 + 退出」用**現有 phases + Timer** 編排,不做專屬 enter/hold/exit 機制:

```
phase 0:  idle action → 跪下祈禱 idle
phase 1:  Timer action(停頓 N 秒) + 冥冥之音(對話行/SNDR)
phase 2:  idle action → 起身 idle(或 scene 結束自然回站姿)
```

作者自由用 phase 序列拼演出。loop/hold 由所選 idle 的性質決定(loop idle 持續到下個 idle 或 scene 結束)。

## Showcase

一個獨立 showcase scene 證明「跪 → 停 → 起」三 phase + 一句台詞。打包 `~/skyrim_mods/ModForgePlayIdle.zip`,結構先驗證(我無法跑遊戲,見 [[ingame-test-workflow]]),再交使用者實機。需先用 `find` 探一個 vanilla 祈禱/下跪 IDLE 並驗證。

## MVP 邊界

- **本輪**:`SceneActionSpec.Idle`、idle action 的 build 分支、`SceneAdapter` 併入、`GenerateSceneFragmentSource` 純產生器 + 測試、`package` 編譯/掛載、showcase scene。
- **之後**:camera shot(CAMS)、手勢序列糖衣、自訂 DAR/OAR 動畫接線、idle event-name(非 IDLE-ref)變體(若有需要)。

## 風險 / 待精修(plan 階段)

- `ScenePhaseFragment` 的確切欄位與 fragment 命名慣例(begin vs end、phase index 對應)需對 Mutagen API 核實——比 quest/TIF 少見的路徑。
- scene fragment 取 actor ref 的 Papyrus 寫法(`GetOwningQuest()` cast + alias property)需在 showcase 驗證可編譯、runtime 取得到 ref。
- 既有 autoStart scene 已在 host quest 上掛 `MFSceneBanterController`(QuestAdapter);PlayIdle fragment 掛在 **SCEN**(SceneAdapter),兩者不同記錄、不衝突,但 package 掛載要分清楚。
