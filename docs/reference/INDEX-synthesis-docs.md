# Synthesis Documentation — Navigation Index

## What this is

A locally-mirrored copy of the [Synthesis](https://mutagen-modding.github.io/Synthesis/) docs (36 pages). Synthesis is a Mutagen-based patcher **framework**: users write small C# "patchers" that transform an existing Skyrim load order, and the Synthesis engine runs them in a pipeline to produce one synthesized patch plugin (`Synthesis.esp`). Paths below are relative to the `reference/` folder.

## Relevant to ModForge

Synthesis is conceptually close to ModForge — both are Mutagen-based plugin tools with a CLI — but the direction differs: **Synthesis PATCHES an existing load order**, while **ModForge GENERATES new content from a JSON spec**. The pages below are the most useful as design inspiration:

- [User Input](mutagen-modding.github.io/Synthesis/devs/User-Input/index.html) — **most relevant**: the "Automatic Settings UI System". You define plain C# settings classes and Synthesis auto-generates both a UI and the JSON config "for free" — directly analogous to ModForge's JSON-spec-from-C# idea. Also covers JSON/XML raw config files, the user data folder, and default-settings handling.
- [Configuring a Patcher at Startup](mutagen-modding.github.io/Synthesis/devs/Configuring-a-Patcher-at-Startup/index.html) — the `SynthesisPipeline` builder API: `AddPatch`, `SetAutogeneratedSettings`, `SetOpenForSettings`, `Run`. Shows how settings classes are wired into the pipeline — a model for how ModForge could expose/declare its spec.
- [Synthesis CLI](mutagen-modding.github.io/Synthesis/Synthesis-CLI/index.html) — the engine's command-line interface (run a profile's pipeline headless, useful on Linux). Good reference for ModForge CLI command/flag shape.
- [Patcher CLI](mutagen-modding.github.io/Synthesis/devs/Patcher-CLI/index.html) — the contract an individual patcher exe must honor (the args Synthesis passes it: what to patch, where to output). Shows a clean CLI-protocol design between engine and worker.
- [Running and Debugging](mutagen-modding.github.io/Synthesis/devs/Running-and-Debugging/index.html) — how a patcher runs standalone (outside the UI) by supplying the load-order/output info the engine would normally provide — relevant to how ModForge bootstraps an environment for local runs.
- [Load Order of Patches](mutagen-modding.github.io/Synthesis/LoadOrder/index.html) — how Synthesis resolves and positions itself in the load order; environment/load-order handling lessons for any Mutagen tool.
- [Overriding Data Folder Path](mutagen-modding.github.io/Synthesis/DataFolder/index.html) — auto-locating the game install via registry vs. manual override; relevant to ModForge environment detection.
- [Coding a Patcher](mutagen-modding.github.io/Synthesis/devs/Coding-a-Patcher/index.html) — minimal patcher skeleton (`SynthesisPipeline.Instance.AddPatch(...).SetTypicalOpen(...).Run(args)` + `RunPatch(IPatcherState)`); the canonical "how a Mutagen mod-tool entry point looks".
- [Runnability Checks](mutagen-modding.github.io/Synthesis/devs/Runnability-Checks/index.html) — declaring pre-run requirement checks that fail fast before work starts; a useful pattern for ModForge spec/precondition validation.
- [Compaction Settings](mutagen-modding.github.io/Synthesis/Compaction/index.html) and [Master Overflow Settings](mutagen-modding.github.io/Synthesis/Master-Overflow-Settings/index.html) — record compaction flags and the 255-master limit / auto-splitting. Relevant since ModForge also writes plugins and must respect these engine constraints.
